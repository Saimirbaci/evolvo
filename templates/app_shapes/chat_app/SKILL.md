# chat_app

A two-pane chat scaffold: a sidebar lists conversations, the main pane
shows the active conversation's message stream + a composer at the
bottom. Each `Conversation` owns its `messages: Vec<Message>` inline so
the whole thread is one JSON document.

## What you get

- Two entities: `Conversation { id, title, messages, createdAt, updatedAt }`
  and `Message { id, role, content, createdAt }` (`role` ∈ user / assistant
  / system).
- Five Tauri commands: `list_conversations`, `load_conversation`,
  `save_conversation`, `delete_conversation`, `send_message`. The first
  four are pure CRUD; `send_message` appends a user message to the
  conversation, persists it, then (when bound to `openrouter`) requests
  an assistant turn and appends it as well.
- One trait: `ChatStore` (object-safe). Default impl `JsonChatStore`
  persists `<workspace>/chat_app/conversations/{id}.json`.
- One Leptos component: `ChatAppPage` (in `ui_app.rs`). Sidebar +
  message stream + composer in a single file.
- ~80 lines of CSS.

## Data interface

```
trait ChatStore: Send + Sync {
    fn list(&self) -> Result<Vec<Conversation>, String>;
    fn load(&self, id: &str) -> Result<Conversation, String>;
    fn save(&self, conv: &Conversation) -> Result<(), String>;
    fn delete(&self, id: &str) -> Result<bool, String>;
}
```

Default impl `JsonChatStore` (`host.rs`).

## Backend seams

### `openrouter` (the headline pairing)

When this binding is set, replace `send_message`'s body so the assistant
turn is generated by an LLM:

```rust
// after persisting the user message:
let history = conv.messages.iter().map(|m| openrouter::Message {
    role: m.role.clone(),
    content: m.content.clone(),
}).collect();
let reply = crate::integrations::openrouter::chat_completion(&state, history).await?;
conv.messages.push(Message {
    id: format!("msg-{}", current_time_unix_ms()),
    role: "assistant".into(),
    content: reply,
    created_at: current_time_unix_ms(),
});
build_store(state.store()).save(&conv)?;
```

Streaming UI: the openrouter integration already has stream support —
hook the assistant message body up to a Leptos signal that the streaming
helper updates token-by-token (see the `// FILL: streaming UI affordance`
marker for where to wire it).

### `sqlite`

Replace `JsonChatStore` with `SqliteChatStore`. Tables:

```sql
CREATE TABLE IF NOT EXISTS conversations (
  id         TEXT PRIMARY KEY,
  title      TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE TABLE IF NOT EXISTS messages (
  id              TEXT PRIMARY KEY,
  conversation_id TEXT NOT NULL REFERENCES conversations(id),
  role            TEXT NOT NULL,
  content         TEXT NOT NULL,
  created_at      INTEGER NOT NULL,
  ordinal         INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS messages_by_conv ON messages(conversation_id, ordinal);
```

`load` issues a join; `save` becomes an upsert + a per-message ordinal
write. Worth doing once a single conversation grows past a few thousand
messages.

### `http_json`

Proxy each operation to `<base>/conversations` / `<base>/conversations/{id}`.

## FILL markers

| Marker                                     | What to fill                                                                                  |
|--------------------------------------------|-----------------------------------------------------------------------------------------------|
| `FILL: system prompt`                      | The system message prepended to every conversation. Default is empty.                          |
| `FILL: assistant turn handling`            | What `send_message` does after persisting the user message — call openrouter, leave for the user, etc. |
| `FILL: streaming UI affordance` (opt)      | Token-by-token streaming render in the message bubble.                                         |
| `FILL: keyboard shortcuts` (opt)           | ⌘⏎ to send, ⌘N for new conversation.                                                          |
